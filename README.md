# SIH26135 — Skilling Intelligence Platform

Prototype for **Smart India Hackathon 2026 — Problem Statement SIH26135**:

> Difficulties in tracking employment outcomes, skill gaps, and the impact of skilling initiatives.

A Skilling Intelligence Platform that connects **training**, **skills**, **employment**, and **labor-market** data so government decision-makers can:
- track employment outcomes of skilling programmes,
- identify **skill gaps** (labour-market demand vs available trained skills),
- evaluate the **impact of skilling initiatives**.

> **Prototype notice:** This is a 6-day college-hackathon prototype. All data is **synthetic demo data** generated by a seed script. **No external government API or real data integration is claimed.** See `docs/PROJECT.md`, `docs/ARCHITECTURE.md` and `docs/DEMO_GUIDE.md`.

## User roles (seeded demo accounts — no public registration)

| Role | Purpose |
| --- | --- |
| **Admin / Government** | Dashboard, employment outcomes, skill-gap analysis, district views, programme impact |
| **Training Provider** | Manage training programmes; view trainee statistics, completion, and outcomes |
| **Trainee** | Profile, education, skills, training history, certifications, employment status/details |

Demo accounts are **seeded** into the database. The prototype does **not** implement public user registration.

## Technology stack

| Layer | Choice |
| --- | --- |
| Backend | Python + **FastAPI** + Uvicorn (`requirements.txt`) |
| Database | **SQLite** via **SQLAlchemy** ORM |
| Validation | Pydantic (ships with FastAPI) |
| Analytics | Plain deterministic **Python + SQLAlchemy queries** (no ML, no pandas in the runtime path) |
| Auth | JWT (**PyJWT**) + role-based access control |
| Frontend | React 18 + Vite, **dependency-free SVG/CSS charts** (no charting library) |
| Reporting UI | Government dashboard |

**Deliberately excluded:** predictive ML, LLMs, blockchain, microservices, Kafka, Redis, Docker, Kubernetes, or real external government integrations.

## Run it

```bash
# Backend
python -m pip install -r requirements.txt
python -m scripts.seed_demo_data            # only on first run / empty database
python -m uvicorn backend.app.main:app --port 8000
# verify: http://localhost:8000/api/health -> {"status":"ok","database":"connected"}

# Frontend
cd frontend && npm install && npm run dev   # http://localhost:5173 (proxies /api to :8000)
```

Full walkthrough, demo sequence and troubleshooting: **`docs/DEMO_GUIDE.md`**.

## Core analytics (all computed server-side from the seeded data)

| Area | Metrics / outputs | Endpoint (admin-only, read-only) |
| --- | --- | --- |
| Employment outcomes | training-completion, employment, relevant-employment & retention rates — overall and per programme | `GET /api/analytics/employment` |
| Skill-gap analysis | demand vs trained supply per skill, gap = demand − supply, high-demand/low-supply flags, district roll-ups | `GET /api/analytics/skill-gap` |
| Programme outcome comparison | ranking by employment outcomes, relevant employment & retention composite — explicitly **not** causal proof | `GET /api/analytics/program-impact` |

Formulas live in one place (`analytics/common/ratios.py`) exactly as specified in `docs/DATABASE.md §3`. The API layer never mutates data.

## Known limitations

- **Synthetic dataset** — every number in the UI comes from seeded demo data, clearly labelled in-app; nothing represents real Maharashtra statistics.
- Single-process SQLite storage; read-only API (no write/update endpoints were in scope).
- With no `SECRET_KEY` configured, JWT secrets regenerate on restart and existing sessions expire (set it via `.env` for a stable demo).
- `scripts/seed_demo_data.py` targets a fresh database file; delete `data/processed/sih26135.db` before re-seeding.
- The optional **AI explanation assistant was intentionally omitted**: the stability criteria were met, but no verifiable API key/network path exists in this environment, so per the Day-6 rules we chose stability over an unverifiable external dependency (`docs/AI_RULES.md` documents the intended rules should it ever be added). The app has zero external-API dependencies and runs fully offline.
