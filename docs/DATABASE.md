## 2. Entities & relationships

| Entity | Purpose | Key fields |
| --- | --- | --- |
| **User** | Single login identity w/ role | id, email, password_hash, role (`admin`/`provider`/`trainee`) |
| **Trainee** | A person being trained | id, user_id, district, education_level, current_skills summary |
| **TrainingProvider** | Runs programmes | id, user_id, name, district |
| **TrainingProgram** | A skilling course | id, provider_id, name, description, duration_weeks, status |
| **Skill** | A skill/category | id, name, category |
| **ProgramEnrollment** | Trainee ↔ program (many-to-many) | trainee_id, program_id, completion_status, certification_status, enrolled_date, completion_date |
| **TraineeSkill** | Trainee ↔ skill (many-to-many) | trainee_id, skill_id, proficiency_level |
| **ProgramSkill** | Program ↔ skill (many-to-many) | program_id, skill_id |
| **Employment** | Employment history of a trainee | id, trainee_id, status, job_role, industry, salary, start_date, still_employed |
| **JobDemand** | Labour-market demand (labour data) | id, job_role, industry, district, required_skill, demand_quantity |

**Relationships:**
- Trainee ↔ TrainingProgram : **many-to-many** via `ProgramEnrollment`
- TrainingProgram → TrainingProvider : many-to-one
- Trainee → Employment : **one-to-many** (history, enables retention)
- Trainee ↔ Skill : many-to-many via `TraineeSkill`
- TrainingProgram ↔ Skill : many-to-many via `ProgramSkill`
- User → Trainee / TrainingProvider : one-to-one identity link

> **Why `Employment` is a history (one-to-many), not a single row:** retention rate requires knowing whether a placed trainee is *still employed* over real time. This resolves the "retention" ambiguity in the problem statement.

## 3. Analytics formulas (single source of truth)

All formulas are deterministic and computed by the `analytics/` package from the DB tables above. Define them here first so the whole team measures the same thing.

### 3.1 Employment outcomes
- **Completion rate** = completed enrollments ÷ total enrollments × 100
- **Employment rate** = employed trainees ÷ trainees available for work × 100
- **Relevant-employment rate** = employed-in-relevant-role trainees ÷ employed trainees × 100
  - "Relevant" = trainee's job_role matches a skill taught in their completed program (role-skill match)
- **Retention rate** = employed trainees still working after N months ÷ placed trainees × 100 (computed from `Employment.start_date` + `still_employed`)

### 3.2 Skill gaps
- Match **labour demand** (`JobDemand`) against **trained-skills supply** (skills taught across completed programs / `TraineeSkill`).
- **Demand** = sum of `JobDemand.demand_quantity` per `required_skill`.
- **Supply** = number of trainees with that skill (proficiency ≥ threshold).
- **Gap** = demand − supply (positive ⇒ skill gap). High |gap| skills are flagged.
- Roll up by **district** for district-wise gaps.

### 3.3 Programme impact
- Per program, compute employment rate, relevant-employment rate, retention rate (section 3.1) among that program's trainees.
- Rank programmes by these outcomes to identify **high- and low-performing** programmes.
- Framing: **outcome comparison / correlation only** — never claimed as strict causal proof.
